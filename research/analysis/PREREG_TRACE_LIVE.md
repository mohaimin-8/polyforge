# Pre-registration: a real trace driving a real cluster (L5)

Frozen and pushed before the campaign runs. The push event is the timestamp
anchor (cardinal rule R1).

## Question (and provenance)

Every trace result this project reports is a **simulation**. Every
`backend: cluster` experiment — `live_soak`, `wave4_live_plane`, the `phase7_*`
set — drives **synthetic** cells (`crud_bursty`, `ai_cacheable`, `tier_mixed`,
`joint_stress`). So the honest statement of the evaluation's shape is:

> **No real trace has ever driven a real cluster.**

`docs/COMPLETION_ROADMAP.md` B4 states this precisely and recommends stating it
rather than closing it, on the grounds that closing it is WP14-sized. Session 42
measured the actual cost and that recommendation is now wrong: the projected
BurstGPT window peaks at **1.377 rps aggregate** (mean 0.316, max single tenant
0.501), because `scale_factor` targets *work units* — mean per-tenant demand
equal to one replica's capacity — not requests per second, and `chat` is
expensive per request. That is ~80x below the synthetic `joint_stress` cell's
~110 AI rps, and it is servable without a GPU.

This campaign closes the gap rather than conceding it.

## What this is NOT

It is **not** a widening of `PREREG_WAVE4_LIVE_PLANE`. That prereg's cell, arms
and hypotheses are frozen and are untouched here; B1 remains unscored and
blocked on substrate throughput. Folding a new comparison into a frozen prereg
after seeing results is exactly the move this project's discipline forbids.

## Design (frozen)

**Demand.** `eval/harness/trace_demand.trace_window(0)`, which calls
`research/analysis/trace_matrix.window_buckets` **directly**. There is one
projection, not two that agree today, so "the live plane replayed the demand the
simulator replayed" is true by construction. Window 0 of
`research/traces/out/burstgpt_real.csv.gz`, scale factor as committed
(75.08666602584566), 8 tenants, 600 s coarse buckets held piecewise-constant
across 10 s control intervals.

**Scored slice: the first 720 buckets (2 hours) of window 0.** Frozen here
before any live run. The full 6 h window would cost 12 h of wall clock across
two arms for no extra inferential value; 2 h is 720 paired control intervals.

**Arms: `jcac` and `hpa_fair`.** Two arms are the minimum that have an
*ordering*, and this pair is the one `RESULTS_BUDGET_PARITY.md` scored BP-H1 on,
so the sim-side expectation is already committed and public.

**Substrate.** kind cluster, `small`, live AI plane enabled. Tier backends are
served by `kaggle_tier_server.py --mock`, whose per-tier delays are
`TIER_BENCH.md`'s committed means (small 1.24 s, mid 1.88 s).

  * **This is the honest departure and it is disclosed, not buried.** Tier
    latency is *injected from the committed bench* rather than generated by a
    model. The tier knob's latency and cost consequences are therefore modelled,
    not served. What IS real: the control loop, the gateway, the semantic cache,
    the replica actuation, PostgreSQL, the arrival process, and the trace.
  * Chosen because the GPU path is blocked for a reason outside this project:
    Kaggle's image ships torch 2.10 (arch list sm_70+) and the free pool grants
    a P100 at sm_60, so no torch operation runs at all
    (`docs/WAVE4_FREE_ROUTE.md` 0b). Waiting for that would defer a result that
    does not depend on it.

**Demand encoding.** k6 `timeUnit: "1m"` with the floor disabled. At the
harness default (`"1s"`, `max(1, round(rps))`) every trace bucket rounds to 0
and is floored to 1: all eight tenants flat at 1 rps, invented traffic in every
idle bucket, **25.3x** the trace's real demand. Pinned by
`test_default_k6_encoding_would_destroy_trace_demand` and
`test_trace_encoding_preserves_shape_idleness_and_volume`.

**Paired sim run.** The same 720 buckets are replayed through `research/jcac_sim`
for both arms, in the same session, from the same projection. The committed 6 h
records are NOT the comparator — they score a different slice.

## Hypotheses (frozen)

* **TL-H1 (primary — ordinal agreement).** On identical trace demand, the
  live cluster's ordering of `jcac` vs `hpa_fair` on **total cost** matches the
  simulator's ordering on the same slice.
  **Falsifier, pre-committed:** if the orderings disagree, that is the result
  and it is the headline of the record. It is not re-run, re-tuned, or widened,
  and it would be direct evidence that sim-only conclusions do not transfer —
  the objection this project has been conceding in prose.

* **TL-H2 (secondary — ordinal agreement on severity).** The same, for
  `mean_violation`. Reported whichever way it lands; a split verdict between
  TL-H1 and TL-H2 is itself informative and is reported as such.

* **TL-H3 (substrate validity, gating).** The run is scoreable only if k6
  delivers the registered demand: failed-request rate <= 1% (k6's own
  `http_req_failed` threshold), and the encoded arrival volume within 5% of the
  projection's. A failure here **voids TL-H1/TL-H2** rather than producing a
  softened claim — the same rule `PREREG_WAVE4_LIVE_PLANE` clause 3 applies to
  its substrate.

* **TL-H4 (descriptive, never gates).** Report the live/sim ratio per arm per
  metric. Absolute agreement is NOT claimed and no threshold is attached: the
  tier latencies are injected, so absolutes cannot be compared. Only the
  *ordering* is under test.

## Outcome handling and stopping rule

One execution per arm. No re-runs on an unfavourable result. Results to
`RESULTS_TRACE_LIVE.md` as measured, TL-H1 disagreement included, and the record
is registered in `scripts/reproduce.py`.

If the sitting aborts for an infrastructure reason (host stall, Docker failure,
k6 abort), the run is **VOID** and re-sat once under this same prereg; two
partial runs are never joined — `RESULTS_LIVE_SOAK_V7.md`'s stray-launcher void
is the precedent. A second abort ends the campaign and the aborts are reported.

## What a PASS does and does not license

A TL-H1 PASS licenses exactly one sentence: *on real trace demand, the live
cluster ranked these two arms as the simulator did.* It does **not** license
"the simulator is validated", does not transfer to arms not run, and does not
make the tier latencies real. The claim is deliberately narrow because the
substrate is honestly narrow.
