## The root cause is one defect, not three

The decisive field is which tiers were actually observed serving under each pin:

- pinned to `small` -> served **['small']**
- pinned to `mid` -> served **['mid', 'small']**

**The tier pin is asymmetric.** Pinning the smaller tier routes exclusively to it; pinning the larger tier still serves a share of requests from the smaller one. That single leak accounts for both failing criteria: `routing_moved` is false by definition, and `latency_moved` is false *because of it* — the larger tier's mean (1557.3 ms) is dragged toward the smaller tier's (1290.5 ms), leaving 266.8 ms against the 322.6 ms the margin requires.

The cache knob is a separate and milder finding: it is **not inert but under-powered**, moving the hit rate by 0.29 against a 0.5 margin.


## The substrate was not the limitation

The free split-host route (`docs/WAVE4_FREE_ROUTE.md`) — a Kaggle P100 serving Qwen2.5-0.5B and Qwen2.5-3B behind a cloudflared quick tunnel — passed its own preflight before the gate ran:

| | |
|---|---:|
| `small` mean (qwen2.5-0.5b-instruct) | 1367.1 ms |
| `mid` mean (qwen2.5-3b-instruct) | 2028.1 ms |
| tier gap | **660.9 ms** vs 341.8 ms threshold |
| models echoed correctly | True |
| round-trip tolerance remaining | 1277 ms |
| slowest tier vs premium SLO (2500 ms) | 2028 ms — 472 ms headroom |
| verdict | **TUNNEL OK (tier gap survives the round-trip)** |

So the tunnel carried a material tier gap and the models answered correctly. **The knobs, not the route, are what failed.** A rented GPU in the same host would not change this verdict.


## Four harness defects, all found by running this path for the first time

`POLYFORGE_EVAL_LIVE_AI=1` had never been set on a real run — WP8b was gated on a GPU the project did not have, and WP8a deliberately runs with it unset. So this code had never executed:

| defect | effect |
|---|---|
| `NameError: EVAL_DIR` in `run_knob_preflight` | the gate could not launch; all 16 runs failed identically |
| `UnicodeEncodeError` printing the gate's own output | the gate crashed reporting its verdict, through cp1252 |
| `knob_preflight.json` written into a `TemporaryDirectory` | the verdict's machine-readable evidence self-deleted — the same loss that took attempt 2's k6 summary |
| tiers ordered **alphabetically** rather than by capability | `sorted(["small","mid"])` = `["mid","small"]`, inverting the probe's ascending-capability convention and **manufacturing** an `ordering_correct: false` |

The fourth is the one that matters for reading this record: it was producing a failure criterion that was an artefact of the harness. With it fixed, `ordering_correct` is **true** and the verdict rests only on the genuine routing leak. The pre-fix readings are retained in `wp8b_substrate_evidence/` so the correction can be checked rather than taken on trust.


## What this does and does not license

**Does not:** any WL-H1 claim. There are no valid runs — the harness reported `valid_runs: 0` — and no arm comparison, cost figure or fairness number from this experiment exists or may be quoted.

**Does:** the finding that the tier knob does not pin exclusively on this build. That is a defect in the system under test, surfaced by a pre-registered gate doing exactly its job, and it is worth more than a scored matrix built on knobs that do not move.

Per the roadmap's risk register — *"WP8: WL-H2 inert knob | SUBSTRATE INADEQUATE, WL-H1 void, report honestly, fix substrate, re-sit"* — the next step is a gateway fix for the asymmetric pin, then a re-sit under a new pre-registration. Neither is done here, and this record does not anticipate their outcome.
