# B1 — the three-knob live plane: the knobs are LIVE, the free route cannot carry the load (WP8b)

Generated by `analysis_wave4_live_plane.py` from evidence committed under `eval/results/wp8b_substrate_evidence/`. Pre-registration: `PREREG_WAVE4_LIVE_PLANE.md`.


## Headline

**WL-H1 is still unscored, and the reason has changed.** The 4 arms x 4 cells matrix has not been run to completion. But the first recorded cause — inert knobs — was wrong, and this record corrects it.

With the operator's Policy reconciler paused for the probe, **WL-H2 PASSES**: `WL-H2 PASS (both knobs live)`. Both knobs move the substrate, and the tier pin is exclusive in both directions.

What blocks the matrix instead is throughput. Under the frozen cell's concurrency, **48.3% of requests failed** (2,880 of 5,963) and k6's delivery threshold aborted the run at 20% of the load window.


## The correction: SUBSTRATE INADEQUATE was a false negative

The WL-H2 probe drives `PUT /admin/tenants/{id}/knobs`. So does the operator: `PolicyReconciler.Reconcile` pushes each Policy's cache and tier levers to that exact endpoint (`internal/operator/controllers/gateway_knobs.go:49`, called from `policy_controller.go:106`). The failing arm was `jcac`, which is in `OPERATOR_SYSTEMS`, so the reconciler was live throughout the probe.

Probe and operator fought over one knob. The same measurement, with and without the reconciler running:

| criterion | reconciler RUNNING | reconciler PAUSED |
|---|---|---|
| cache hit @64 MB vs @0 MB | 1.00 vs **0.71** (delta 0.29) | 1.00 vs **0.00** (delta 1.00) |
| cache live (margin 0.5) | **False** | **True** |
| pinned `small` served | ['small'] | **['small']** |
| pinned `mid` served | **['mid', 'small']** | **['mid']** |
| `routing_moved` | **False** | **True** |
| `latency_moved` | False | **True** |
| verdict | SUBSTRATE INADEQUATE | **WL-H2 PASS** |

One mechanism explained every failing criterion. The probe pinned `mid`; the next reconcile wrote the Policy's tier back; the probe observed both tiers. The asymmetry followed too — the reconciler's own value wins, so pinning *that* tier looked exclusive while pinning the other leaked. The cache read the same way: the probe set `cache_size_mb=0`, the reconciler wrote the Policy's size back, and the hit rate at "0 MB" came out 0.71 instead of 0.00.

**The gateway was never at fault.** `TestTierPinIsExclusiveAcrossManyRequests` pins each tier, sends the same eight requests the probe does, and asserts the pin holds for every one; it passes. The pre-existing `TestTierKnobMovesRoutingAndTelemetry` sends **one** request per tier, which is why an intermittent leak survived it.

**The fix** pauses the reconciler for the probe and restores it immediately after (`_operator_paused`). WL-H2 measures the *substrate*, not the arm's controller. The probe runs before the load window, so no scored behaviour changes.


## What actually blocks the matrix now

With the gate passed, the run proceeded to load and failed there:

| | |
|---|---:|
| requests | 5,963 |
| **failed** | **48.3%** (2,880) |
| iteration duration median | 58 ms |
| iteration duration max | **60 s** |
| load window completed | **20%** (1 m 01 s of 5 m 10 s) |
| aborted by | `http_req_failed` threshold `rate<0.01` |

The shape is the diagnosis. The median request is fast — cache hits and CRUD — while the tail sits exactly on a **60 second timeout**. A free Kaggle P100 serialises generation, so the frozen cell's ~218 concurrent virtual users queue behind one GPU until they time out.

**This is why the tunnel preflight could not catch it.** `tunnel_preflight.py` issues **sequential** probes — eight per tier — and measures round-trip latency. It cannot observe queueing, because it never creates any. On this session's route it reported:

- tier gap **551.8 ms** vs 482.1 ms threshold — material
- slowest tier 2480 ms against a 2500 ms premium SLO — only **20 ms** of headroom
- verdict **TUNNEL OK (tier gap survives the round-trip)**

A sequential preflight that passes therefore does **not** license a concurrent matrix. That is a limitation of the free split-host route which `docs/WAVE4_FREE_ROUTE.md` does not currently state, and it should: the route's own quota table discusses GPU-hours and round-trip latency, never throughput under load.


## Five harness defects, all found by running this path for the first time

`POLYFORGE_EVAL_LIVE_AI=1` had never been set on a real run — WP8b was gated on a GPU the project did not have, and WP8a deliberately runs with it unset. So none of this code had ever executed:

| defect | effect |
|---|---|
| `NameError: EVAL_DIR` in `run_knob_preflight` | the gate could not launch; all 16 runs failed identically |
| `UnicodeEncodeError` printing the gate's own output | the gate crashed reporting its verdict, through cp1252 |
| `knob_preflight.json` written into a `TemporaryDirectory` | the verdict's evidence self-deleted — the loss that took attempt 2's k6 summary |
| tiers ordered **alphabetically**, not by capability | `sorted(["small","mid"])` inverted the probe's ascending-capability convention and **manufactured** an `ordering_correct: false` |
| the probe raced the operator's reconciler | **manufactured the SUBSTRATE INADEQUATE verdict itself** |

The last two are the serious ones: each was producing a failure that was an artefact of the apparatus rather than a property of the system under test. A pre-registered gate is only as trustworthy as the first time it is actually executed.


## What this does and does not license

**Does not:** any WL-H1 claim. There are no valid runs, and no arm comparison, cost figure or fairness number from this experiment exists or may be quoted.

**Does:** the finding that both knobs are live on this build, evidenced by a passing WL-H2 with the tier pin exclusive in both directions and a cache delta of 1.00. The earlier inert-knob reading is withdrawn.

**Also does:** the finding that a free serialising GPU cannot carry this cell's concurrency, and that a sequential preflight cannot detect that. Both belong in the route documentation before anyone spends another session on it.

Scoring B1 needs a substrate that serves the cell's concurrency — a rented GPU, a smaller frozen cell under a NEW pre-registration, or batched serving on the free pool. The prereg's cell is frozen, so the second option is a different experiment, not an adjustment to this one.
