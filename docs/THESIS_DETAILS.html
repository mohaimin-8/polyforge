Project Description

Abstract

Modern backend platforms are converging: a single Kubernetes cluster now commonly hosts both classic CRUD services (e-commerce, banking, SaaS APIs) and AI workloads (chatbots, RAG pipelines, agentic systems) for the same tenants. These two workload classes have fundamentally different scaling, caching, and routing characteristics — yet existing autoscalers (HPA, KEDA), caches (Redis LRU), and routers treat them uniformly. The result is over-provisioned CRUD pods, wasted cache memory holding stale AI completions, expensive frontier-model calls for queries a small model could answer, and tenant noisy-neighbor failures during AI burst loads.

This thesis designs, builds, and evaluates PolyForge — an adaptive multi-tenant backend platform that hosts hybrid CRUD + AI workloads on shared infrastructure, observes per-tenant workload signatures online, and jointly tunes replicas, cache allocation, and model routing via a custom Kubernetes operator. The platform is built in Go for the data plane, exposes both REST and gRPC, and integrates a semantic LLM gateway with Redis + pgvector — all instrumented end-to-end with OpenTelemetry.

The primary invention is the Joint Cross-Layer Adaptive Controller (JCAC) — a Model-Predictive Control loop that runs as a Kubernetes operator and jointly optimizes (replicas × cache size × model tier) per tenant, driven by a lightweight online Workload Classifier that labels request streams as CRUD-bursty, CRUD-steady, AI-cacheable, AI-uncacheable, or agentic-multistep. Existing autoscalers tune layers independently; JCAC exploits their coupling. No published work jointly optimizes scaling + caching + routing for hybrid workloads.

The empirical contribution is a systematic benchmark on three real-world traces — Azure Functions trace, Alibaba microservices trace, and LMSYS-Chat-1M — replayed in a multi-tenant configuration. Five baselines (HPA, KEDA, FIRM, static routing, GPTCache LRU) are compared across 5 workload classes × 4 tenant-mix profiles × 3 cluster sizes × 30 repetitions = 1,800+ experiment runs, with cost ($), p99 latency, SLO violation rate, and Jain's fairness index reported with ANOVA + Cohen's d.

Beyond benchmarking, the platform delivers six engineering contributions: (1) hybrid workload classifier, (2) joint MPC controller, (3) cost-aware semantic cache eviction, (4) tenant-fair adaptive isolation with eBPF-based noisy-neighbor detection, (5) open mixed-workload benchmark suite, (6) production-grade Helm chart polyforge-operator released on Artifact Hub with CRDs, RBAC, and OpenTelemetry hooks.

The output is one comprehensive thesis paper targeting Future Generation Computer Systems (FGCS, IF ~7, Elsevier). The paper unifies all six contributions into a single coherent narrative — from the workload classifier through cost-aware caching to the joint MPC controller — anchored on the 1,800-run evaluation. FGCS is chosen for its breadth (systems + algorithms in one venue) and ~3-month average review time. Backup venue: IEEE Access (IF 3.6, 21-day review) if a fast acceptance is needed before graduation.

6 Novel Contributions

01
Joint Cross-Layer Adaptive Controller (JCAC) — The Invention
A Model-Predictive Control loop that runs as a Kubernetes operator and jointly optimizes three layers — pod replicas, cache memory budget, and LLM model tier — per tenant. Existing autoscalers (HPA, KEDA), caches (Redis LRU), and routers operate independently and miss cross-layer coupling: scaling up replicas without enlarging cache wastes the new compute on cache misses; routing to a cheaper model without warming its KV cache adds tail latency. JCAC plans 60 seconds ahead, respects per-tenant SLO and fairness constraints, and converges within 4 control cycles in our evaluation. No published work jointly optimizes these three layers for hybrid CRUD + AI workloads.
Fills: per-layer baselines (HPA + LRU + static routing) ignore cross-layer coupling — 30%+ unrealized gains
The invention
02
Hybrid Workload Classifier
An online classifier that labels each tenant's request stream every 10 seconds into one of five classes: CRUD-bursty, CRUD-steady, AI-cacheable, AI-uncacheable, agentic-multistep. Features include RPS variance, payload size distribution, cache hit-rate signature, and embedding-space density. Drives downstream policy in JCAC. Trained on Azure + Alibaba + LMSYS traces with 95%+ F1 on held-out sets.
Fills: prior workload classification work is offline-only or single-class (no hybrid CRUD+AI taxonomy)
Novel
03
Cost-Aware Semantic Cache Eviction
Eviction weight = f(recompute_cost_$, hit_probability, staleness_decay, embedding_density). LRU evicts old entries indiscriminately — but a $0.50 cached GPT-4 completion is more valuable than a $0.001 cached SQL result. We evict to maximize $-saved per KB rather than recency. Compared head-to-head against LRU, LFU, GDSF, ARC, and GPTCache.
Fills: GPTCache, MeanCache, SCALM use threshold-only eviction; no cost-weighted policy exists
Novel
04
Tenant-Fair Adaptive Isolation
eBPF-based noisy-neighbor detection (CPU stalls, memory pressure events, syscall storms per tenant) feeds a fairness-weighted resource allocator using Jain's fairness index as objective. When budget exceeded, the system maximizes fairness-weighted SLO satisfaction rather than total throughput. Critical for SaaS production.
Fills: K8s ResourceQuota is static; existing fair schedulers ignore SLO weighting
Novel
05
Mixed-Workload Benchmark Suite
Open-source benchmark that mixes Azure Functions trace (CRUD-bursty), Alibaba microservices trace (CRUD-steady), and LMSYS-Chat-1M (AI workloads) into reproducible multi-tenant scenarios. CSV manifest, k6 replay scripts, Docker harness. The first benchmark designed for hybrid workloads — directly citable by future research.
Fills: existing benchmarks (CloudSuite, DeathStarBench, vLLM-bench) are single-class
Artifact
06
polyforge-operator on Artifact Hub
Production-grade Helm chart published to Artifact Hub: 4 CRDs (Tenant, WorkloadProfile, Policy, Budget), reconcile loops with proper finalizers, RBAC scoped to namespaces, OpenTelemetry tracing of every reconciliation, status subresource for kubectl observability. Installable in any cluster with one command.
Fills: existing autoscaler operators (HPA, KEDA, Karpenter) don't expose joint cross-layer policy
