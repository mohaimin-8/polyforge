# `requirements.txt` is deliberately loose: the harness and the simulator
# should keep working as their dependencies move, and CI catching a break
# early is worth more than a frozen tree. **Byte-identical reproduction is a
# different claim** — `scripts/reproduce.py` asserts that a record regenerates
# to the same bytes, and a `>=` floor cannot support that: the reproduce job
# installed pandas 3.0.5 and numpy 2.5.2 against the pandas 2.2.3 / numpy 2.2.3
# that wrote the records, so the gate was red in CI while green on the author's
# machine.
#
# So the gate installs these pins, and the byte-identity claim is scoped to
# them. A reviewer reproducing the paper's numbers should use this file; anyone
# running the system should use `requirements.txt`.
#
# To move a pin: bump it here, re-run `python scripts/reproduce.py`, and if a
# record drifts, DO NOT re-freeze it to match — that is a finding about the
# dependency, and it belongs in the record's own supersession, not in a silent
# regeneration.
